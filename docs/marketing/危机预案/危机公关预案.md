## 一、危机分级

| 级别 | 定义 | 响应时间 | 决策人 |
|------|------|----------|--------|
| 🟢 一般 | 单个用户投诉，无传播 | 24小时内 | 客服 |
| 🟡 预警 | 3人以上同类投诉 / 小范围负面 | 4小时内 | 运营负责人 |
| 🟠 严重 | 社交媒体曝光 / 媒体报道 | 1小时内 | 创始人 |
| 🔴 紧急 | 大规模数据泄露 / 服务中断 | 30分钟内 | 创始人+全员 |

## 二、常见危机场景与应对

### 场景1：服务器宕机/服务中断

**判断标准**：用户无法使用核心功能超过30分钟

**应对流程**：
```
1. 立即响应（5分钟内）
   · 技术团队确认问题
   · 估算恢复时间

2. 对外公告（30分钟内）
   公告模板：
   "尊敬的用户，我们遇到短暂的服务器问题，
   技术团队正在紧急修复，预计XX分钟内恢复。
   给您带来的不便深表歉意。"

3. 更新进度（每30分钟）
   在官网/App内更新恢复进度

4. 事后复盘（24小时内）
   · 根因分析
   · 预防措施
   · 用户补偿方案（如延长会员时长）
```

---

### 场景2：负面评价/差评

**判断标准**：应用商店/社交媒体出现大量负面评价

**应对流程**：
```
1. 监测（每日检查）
   · 应用商店评分变化
   · 小红书/知乎/微博提及
   · 社群负面反馈

2. 分类处理
   · 单个差评：24小时内私信沟通解决
   · 集中差评：4小时内发布官方说明
   · 恶意攻击：保留证据，平台举报

3. 官方回应模板
   "感谢用户的反馈，我们已认真记录问题，
   技术团队正在排查修复。
   如有具体问题，请联系support@...，
   我们将在24小时内回复。"

4. 后续跟进
   · 问题解决后主动联系用户
   · 邀请用户更新评价
   · 发布修复公告
```

---

### 场景3：数据安全问题

**判断标准**：用户数据泄露/被黑客攻击

**应对流程**：
```
1. 立即止损（1小时内）
   · 停止受影响服务
   · 保留日志证据
   · 通知安全团队

2. 用户通知（24小时内）
   通知模板：
   "我们检测到潜在的安全风险，
   为保护您的数据安全，我们已采取以下措施：
   · 已重置相关系统
   · 建议修改密码
   · 已加强安全审计
   如有任何问题请联系：support@..."

3. 监管报备（48小时内）
   · 向网信办/公安报备
   · 配合调查

4. 公开声明（72小时内）
   · 发布详细事件说明
   · 道歉+整改措施
   · 第三方安全审计结果
```

---

### 场景4：竞品恶意竞争

**判断标准**：竞品发起恶意攻击/抹黑

**应对流程**：
```
1. 确认事实
   · 收集证据（截图/录音）
   · 确认是否为恶意行为

2. 不主动回应
   · 不在公开渠道对骂
   · 专注做好产品

3. 法律手段
   · 发律师函
   · 平台投诉
   · 必要时诉讼

4. 用户教育
   · 在社群内正面引导
   · 分享真实用户评价
```

---

### 场景5：PR/媒体负面报道

**判断标准**：媒体发布负面报道

**应对流程**：
```
1. 了解报道内容
   · 准确理解报道角度
   · 区分事实与观点

2. 准备回应材料
   · 事实澄清
   · 数据支撑
   · 用户好评

3. 主动沟通
   · 联系记者/编辑
   · 提供补充信息
   · 安排采访

4. 反向宣传
   · 发布正面内容
   · 邀请媒体正面报道
```

## 三、危机沟通原则

### 3.1 黄金原则

1. **速度第一**：危机发生后越快响应越好
2. **真诚道歉**：不推诿，不找借口
3. **统一口径**：所有对外信息保持一致
4. **持续更新**：定期向用户通报进展

### 3.2 禁忌行为

❌ 删除负面评论（激化矛盾）
❌ 攻击用户/竞品（扩大争议）
❌ 长时间不回应（显得傲慢）
❌ 内部争论公开化（显得不专业）
❌ 推卸责任（失去信任）

### 3.3 回复公式

```
共情 + 承认 + 方案 + 承诺 + 联系方式
```

**示例**：
```
"非常理解您的 frustration（共情）
是我们产品的问题导致您体验不佳（承认）
我们已经定位到问题，正在紧急修复（方案）
预计2小时内恢复，恢复后为您延长7天会员（承诺）
如有任何问题请联系：support@...（联系方式）"
```
