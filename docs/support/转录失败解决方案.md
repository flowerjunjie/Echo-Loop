# 转录失败解决方案

## 问题现象
App转录功能持续失败，后端日志显示：
```
[TRANSCRIBE] audio not found | sha256=95eebf568f444c6651d9d1a255d085550b9deb097c43a02f526206f6533f6cb5
```

## 问题原因
App本地缓存了旧的音频文件SHA256引用，但该文件在服务端已被删除。

## 解决方案

### 方案1：彻底清除App数据（推荐）

#### 步骤1：卸载App
```
手机设置 → 应用管理 → 灵犀AI英语听说 → 卸载
```

#### 步骤2：重新安装
```bash
# 方法A：ADB安装
adb install /www/workspace/Echo-Loop-landing/apk/app-release.apk

# 方法B：浏览器下载
访问 http://38.55.146.160:8100/ 下载最新APK
```

#### 步骤3：重新测试
1. 打开App
2. 重新登录（使用邮箱验证码）
3. 导入**全新的音频文件**（不要选择之前的文件）
4. 等待上传成功提示
5. 提交转录任务

### 方案2：使用离线ASR

如果网络转录仍然有问题，可以使用离线ASR：

```
设置 → 离线ASR设置 → 启用
```

优点：
- 完全离线，无需联网
- 不依赖服务器
- 响应更快
- 保护隐私

### 方案3：检查App网络配置

如果以上方案都失败，检查App是否正确配置了API地址：

1. 打开App
2. 进入「设置」
3. 查看「后端地址」或「API配置」
4. 确认地址为：`http://38.55.146.160:3003`
5. 如果不是，修改并保存

## 验证转录功能是否正常

使用curl测试：
```bash
curl -X POST http://38.55.146.160:3003/api/v2/user-audio/submit-transcription \
  -H "Content-Type: application/json" \
  -d '{"sha256":"211c23ae2aeed2410cec37bf58f4e90c249898e2718b1416689f259e6d178f43","language":"en"}'
```

预期结果：
```json
{
  "cached": true,
  "transcript": {
    "sentences": [...],
    "fullText": "..."
  }

```

## 常见问题

### Q1: 清除数据后仍然失败？
A: 确保导入的是全新的音频文件，不要复用旧的。

### Q2: 上传一直卡住？
A: 检查网络连接，确保能访问 `http://38.55.146.160:3003`

### Q3: 转录一直显示「进行中」？
A: 转录需要30-60秒，请耐心等待。如果超过2分钟，可能是服务器负载高。

### Q4: 如何使用离线ASR？
A: 设置 → 离线ASR设置 → 启用。首次使用需要下载语音模型（约50MB）。
